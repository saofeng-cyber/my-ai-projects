这四种索引方式都是为了解决RAG（检索增强生成）中不同层次的检索需求而设计的。它们在**检索单位**和**上下文保留**之间做了不同的权衡。

为了方便选型，我将这四种索引总结为下表，然后逐一展开：

| 索引类型 | 核心思想 | 最佳适用场景 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **摘要索引** | 先精炼后检索 | 长文档全局概括、跨文档主题问答 | 上下文窗口友好、检索速度快、抗噪声强 | 摘要损失细节、不适合精确信息查找 |
| **父子索引** | 以小搜大，保留上下文 | 需要精确引证、深层语义理解的复杂问答 | 检索精度高、上下文保留好、可解释性强 | 实现相对复杂、需维护双向关系 |
| **假设性问题索引** | 让文档自己回答问题 | 问答匹配度要求极高、用户问题多变 | 语义对齐好、召回率高、泛化性强 | 生成成本高、覆盖不全、幻觉风险 |
| **元数据索引** | 给数据贴标签进行筛选 | 数据分类明确、需按属性筛选的场景 | 筛选效率极高、逻辑确定性强、可过滤噪声 | 依赖人工标注、无法处理语义模糊问题 |

---

### 1. 摘要索引

-   **核心思想**：先对文档进行总结（或由大模型生成摘要），然后只对摘要进行索引和检索。找到相关摘要后，将对应的原始文档内容作为上下文送给大模型。
-   **特征**：
    -   **粒度粗**：检索单位是高度浓缩的摘要。
    -   **语义压缩**：将长篇内容压缩成核心要点，节省Token。
-   **应用场景**：
    -   处理超长文档（如整本书、年度报告），需要把握全局脉络时。
    -   用户问题偏向于“概括性”（如：“这本书主要讲了什么？”）。
    -   对检索速度要求极高，且能容忍一定细节丢失的场景。

### 2. 父子索引

-   **核心思想**：将文档拆分为不同粒度。通常将大段文本（父节点）再切分成小段（子节点）。**检索时在子节点（小块）中搜索**，找到最相关的小块后，**返回其对应的父节点（大块）**作为上下文。
-   **特征**：
    -   **双向关系**：维护了片段（子）与上下文（父）之间的映射。
    -   **精度+上下文兼顾**：利用小片段提高检索的精确度（精准定位答案），利用大片段保证上下文的完整性（防止信息缺失）。
-   **应用场景**：
    -   需要精确引证来源的场景（如：法律条文检索、学术论文引用）。
    -   文档结构复杂，单一句子需要依赖段落整体才能理解的场景。
    -   对检索结果的可解释性要求较高时。

### 3. 假设性问题索引

-   **核心思想**：让大模型“阅读”每个文档块，并针对每个块**生成一个或多个假设性的问题**（即：想象一下用户会问什么问题才能得到这个答案）。然后对这些假设性问题建立索引，并与原文档块关联。检索时，拿用户的真实问题去匹配这些假设性问题。
-   **特征**：
    -   **问答对齐**：将“文档-文档”的匹配，转换为“问题-问题”的匹配，通常在向量空间中效果更好。
    -   **视角转换**：从文档作者的视角转换为提问者的视角。
-   **应用场景**：
    -   构建问答系统，且用户提问风格多变（口语化、不专业）时。
    -   文档内容与用户提问方式存在较大“语义鸿沟”（如专业文档 vs. 小白提问）。
    -   需要提高特定垂直领域问答的召回率。

### 4. 元数据索引

-   **核心思想**：不直接索引文本内容，而是索引文档的结构化信息（如：作者、日期、类别、文件名、章节号等）。通常与向量检索结合使用，作为**预过滤器**（先筛选范围，再语义搜索）或**后过滤器**（先语义搜索，再按条件筛选）。
-   **特征**：
    -   **结构化**：数据是键值对形式，精确匹配或范围查询。
    -   **高效筛选**：极大地缩小搜索范围，提升检索效率和准确性。
-   **应用场景**：
    -   数据天然带有结构化标签（如：知识库分属不同部门、邮件带有收发件人）。
    -   需要按时间、地域、类别等维度进行检索的业务系统。
    -   需要结合业务规则（如权限控制）进行RAG的场景。

### 选型建议

在具体项目中，这几种索引通常不是互斥的，而是组合使用的：

1.  **如果项目刚起步，文档质量一般**：优先考虑**父子索引**。它最稳定，既能保证找到答案，又能提供完整的上下文，是兼顾检索精度和召回率的“万金油”。
2.  **如果用户提问非常随意，且预算充足**：可以在父子索引的基础上，对核心文档块增加**假设性问题索引**，作为补充检索链路。
3.  **如果文档非常长，且问题都是宏观总结**：可以考虑**摘要索引**作为第一层检索，如果摘要没命中，再降级到父子索引进行细粒度搜索。
4.  **如果数据维度丰富**：一定要加上**元数据索引**。通过元数据过滤掉无关数据，能显著提升向量检索的效果，甚至有时只靠元数据过滤和关键词检索就能解决问题。
